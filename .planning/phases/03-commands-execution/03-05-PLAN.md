**packages/plugin/tests/helpers/companion-runner.ts** — Helper to run the bundled companion as a child process:

```typescript
import { execFile } from 'node:child_process';
import { join } from 'node:path';

const COMPANION_PATH = join(__dirname, '..', '..', 'scripts', 'agents-companion.cjs');

export interface CompanionResult {
  stdout: string;
  stderr: string;
  exitCode: number;
  json: Record<string, unknown> | null;
}

export function runCompanion(
  args: string[],
  opts?: { cwd?: string; env?: Record<string, string> }
): Promise<CompanionResult> {
  return new Promise((resolve) => {
    execFile('node', [COMPANION_PATH, ...args], {
      cwd: opts?.cwd ?? process.cwd(),
      env: { ...process.env, ...opts?.env },
      timeout: 30_000,
    }, (error, stdout, stderr) => {
      const exitCode = error?.code ? Number(error.code) : (error ? 1 : 0);
      let json: Record<string, unknown> | null = null;
      try { json = JSON.parse(stdout.trim()); } catch { /* not JSON */ }
      resolve({ stdout: stdout.trim(), stderr: stderr.trim(), exitCode, json });
    });
  });
}
```

Note: The `error.code` from `execFile` may be `'ERR_CHILD_PROCESS_STDIO_MAXBUFFER'` or a string exit signal. Handle by checking `error` and its `code` property. Use the child's actual exit code if available via a different approach if needed — test empirically. The key contract is: `exitCode === 0` on success, `exitCode !== 0` on error.

**packages/plugin/tests/helpers/temp-env.ts** — Helper to create isolated temp directories for each test:

```typescript
import { mkdirSync, writeFileSync, rmSync, mkdtempSync } from 'node:fs';
import { join } from 'node:path';
import { tmpdir } from 'node:os';
import { afterEach, beforeEach } from 'vitest';

export interface TestEnv {
  tmpDir: string;
  pluginDataDir: string;
  workspaceDir: string;
}

let currentEnv: TestEnv | null = null;

export function useTempEnv(): { getEnv: () => TestEnv } {
  beforeEach(() => {
    const tmpDir = mkdtempSync(join(tmpdir(), 'companion-test-'));
    const pluginDataDir = join(tmpDir, 'plugin-data');
    const workspaceDir = join(tmpDir, 'workspace');
    mkdirSync(pluginDataDir, { recursive: true });
    mkdirSync(workspaceDir, { recursive: true });
    currentEnv = { tmpDir, pluginDataDir, workspaceDir };
  });

  afterEach(() => {
    if (currentEnv) {
      rmSync(currentEnv.tmpDir, { recursive: true, force: true });
      currentEnv = null;
    }
  });

  return {
    getEnv: () => {
      if (!currentEnv) throw new Error('Test env not initialized');
      return currentEnv;
    }
  };
}

export function writeAgentsConfig(workspaceDir: string, config: Record<string, unknown>): void {
  const dir = join(workspaceDir, '.claude');
  mkdirSync(dir, { recursive: true });
  writeFileSync(join(dir, 'agents.json'), JSON.stringify(config, null, 2), 'utf-8');
}
```

**packages/plugin/tests/companion-job-lifecycle.test.ts** — Integration tests for the full background job lifecycle.

These tests verify the dispatch -> status -> result -> cancel flow using fake CLI shims. The key challenge is timing: the worker runs as a detached process, so tests need to poll status until it transitions.

**Helper — poll for job completion:**
```typescript
async function pollJobStatus(
  env: { pluginDataDir: string; workspaceDir: string },
  jobId: string,
  targetStatuses: string[],
  timeoutMs = 15000,
  intervalMs = 500
): Promise<CompanionResult> {
  const start = Date.now();
  while (Date.now() - start < timeoutMs) {
    const result = await runCompanion(['status', jobId], {
      cwd: env.workspaceDir,
      env: { CLAUDE_PLUGIN_DATA: env.pluginDataDir, PATH: process.env.PATH! }
    });
    if (result.json && targetStatuses.includes(result.json.status as string)) {
      return result;
    }
    await new Promise(r => setTimeout(r, intervalMs));
  }
  throw new Error(`Job ${jobId} did not reach ${targetStatuses.join('|')} within ${timeoutMs}ms`);
}
```

**Test cases:**

1. **Background dispatch returns job-id immediately:**
   - Write valid agents config with `claude_local` adapter
   - Put fake `claude` shim (from Phase 2 fixtures or newly created) on PATH that runs in `__ADAPTER_TEST_MODE=success` — but add a small `sleep 2` to simulate work
   - Run `task --agent test-agent --background "test prompt"` with CLAUDE_PLUGIN_DATA set
   - Assert response contains `{ jobId: string, status: 'pending' }` and returns within 2 seconds (before shim finishes)

2. **Status transitions from pending to running to completed:**
   - Dispatch background job as above
   - Poll status until `running` (worker updates pid and status)
   - Poll status until `completed`
   - Assert final status JSON has `status: 'completed'` and `endTime` is set

3. **Result retrieval after completion:**
   - After test 2's job completes, call `result <job-id>`
   - Assert response contains `{ jobId, output: "..." }` with the shim's output

4. **Result error for non-completed job:**
   - Dispatch a background job with a shim that sleeps 10s
   - Immediately call `result <job-id>` before it completes
   - Assert error: `Job not completed. Current status: ...`

5. **Cancel a running job:**
   - Dispatch a background job with a shim that sleeps 10s
   - Poll until status is `running`
   - Call `cancel <job-id>`
   - Assert response: `{ jobId, status: 'cancelled' }`
   - Poll status again to confirm `cancelled`

6. **Cancel error for completed job:**
   - Use a fast shim, wait for completion
   - Call `cancel <job-id>`
   - Assert error: `Cannot cancel job in 'completed' state`

7. **Status error for nonexistent job:**
   - Call `status nonexistent-uuid`
   - Assert error: `Job not found`

**Fake CLI shims:** Create shims in `packages/plugin/tests/fixtures/shims/` following the Phase 2 pattern:

`claude` shim (shell script):
```sh
#!/bin/sh
if [ "$__ADAPTER_TEST_MODE" = "success" ]; then
  sleep "${__ADAPTER_TEST_DELAY:-0}"
  echo '{"result":"test-output-from-shim"}'
  exit 0
elif [ "$__ADAPTER_TEST_MODE" = "error" ]; then
  echo "adapter error" >&2
  exit 1
fi
echo "unknown mode" >&2
exit 1
```

The `__ADAPTER_TEST_DELAY` env var controls how long the shim runs (for testing background job timing). Default 0 for fast tests, set to 2-5 for cancel tests.

Set PATH to include the shims directory and set `__ADAPTER_TEST_MODE=success` in the environment passed to `runCompanion`.

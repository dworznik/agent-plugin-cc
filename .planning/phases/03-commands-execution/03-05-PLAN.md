**packages/plugin/tests/companion-job-lifecycle.test.ts** — Integration tests for the full background job lifecycle.

These tests verify the dispatch -> status -> result -> cancel flow using fake CLI shims. The key challenge is timing: the worker runs as a detached process, so tests need to poll status until it transitions.

**Helper — poll for job completion (with tightened timeouts per scope warning):**
```typescript
async function pollJobStatus(
  env: { pluginDataDir: string; workspaceDir: string },
  jobId: string,
  targetStatuses: string[],
  timeoutMs = 8000,
  intervalMs = 250
): Promise<CompanionResult> {
  const start = Date.now();
  while (Date.now() - start < timeoutMs) {
    const result = await runCompanion(['status', jobId], {
      cwd: env.workspaceDir,
      env: { CLAUDE_PLUGIN_DATA: env.pluginDataDir, PATH: process.env.PATH! }
    });
    if (result.json && targetStatuses.includes(result.json.status as string)) {
      return result;
    }
    await new Promise(r => setTimeout(r, intervalMs));
  }
  throw new Error(`Job ${jobId} did not reach ${targetStatuses.join('|')} within ${timeoutMs}ms`);
}
```

IMPORTANT: Use `__ADAPTER_TEST_DELAY=0.5` (500ms) for "slow" shims that need cancel testing, NOT 2-5 seconds. The 500ms delay is enough to test the cancel-during-execution flow while keeping total test time under 10 seconds. Use `__ADAPTER_TEST_DELAY=0` for fast completion tests.

**Test cases:**

1. **Background dispatch returns job-id immediately:**
   - Write valid agents config with `claude_local` adapter
   - Put fake `claude` shim on PATH with `__ADAPTER_TEST_MODE=success` and `__ADAPTER_TEST_DELAY=0.5`
   - Run `task --agent test-agent --background "test prompt"` with CLAUDE_PLUGIN_DATA set
   - Assert response contains `{ jobId: string, status: 'pending' }` and returns within 1 second (before shim finishes)

2. **Status transitions from pending to running to completed:**
   - Dispatch background job with `__ADAPTER_TEST_DELAY=0`
   - Poll status until `completed` (fast shim, should complete in under 2s)
   - Assert final status JSON has `status: 'completed'` and `endTime` is set

3. **Result retrieval after completion:**
   - After test 2's job completes, call `result <job-id>`
   - Assert response contains `{ jobId, output: "..." }` with the shim's output

4. **Cancel a running job:**
   - Dispatch a background job with `__ADAPTER_TEST_DELAY=3` (long enough to catch while running)
   - Poll until status is `running`
   - Call `cancel <job-id>`
   - Assert response: `{ jobId, status: 'cancelled' }`
   - Poll status again to confirm `cancelled`

5. **Cancel error for completed job:**
   - Use a fast shim (`__ADAPTER_TEST_DELAY=0`), wait for completion
   - Call `cancel <job-id>`
   - Assert error: `Cannot cancel job in 'completed' state`

6. **Status error for nonexistent job:**
   - Call `status nonexistent-uuid`
   - Assert error: `Job not found`

Set PATH to include the shims directory and set `__ADAPTER_TEST_MODE=success` in the environment passed to `runCompanion`.

**Important timing notes:**
- Use 8s timeout for poll loops (sufficient for CI, well under 10s per-test target)
- Use 250ms poll interval (faster feedback than 500ms, lower total test time)
- Each test gets a fresh temp dir via `useTempEnv()`
- Background worker inherits env from companion, which inherits from test — set PATH and __ADAPTER_TEST_MODE in the env passed to `runCompanion`
